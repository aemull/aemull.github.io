## Pendahuluan

Pada pengujian ini saya melakukan assessment terhadap kontrol sesi berdasarkan:

- **WSTG-SESS-02 — Testing for Cookies Attributes**
- **WSTG-SESS-06 — Testing for Session Fixation**

Target aplikasi berjalan pada stack:

- Debian
- Nginx
- PHP-FPM
- Laravel

Tujuan utama pengujian adalah memastikan konfigurasi keamanan yang tepat diatur untuk cookie dan memastikan tidak terdapat celah **session fixation**.

---

# WSTG-SESS-02 — Testing for Cookies Attributes

Pengujian ini berfokus pada atribut keamanan cookie seperti:

- `Secure`
- `HttpOnly`
- `SameSite`
- Masa berlaku (Expiration)
- Scope cookie

---

## Sebelum Hardening

Hasil pemeriksaan header menggunakan `curl -I`:

```

carmen@dvwa:~$ curl -I [https://192.168.20.145](https://192.168.20.145) -k

```

Response:

```

HTTP/1.1 200 OK
Set-Cookie: XSRF-TOKEN=...; expires=Fri, 27 Mar 2026 06:35:02 GMT; Max-Age=2592000; path=/
Set-Cookie: laravel_session=...; expires=Fri, 27 Mar 2026 06:35:02 GMT; Max-Age=2592000; path=/
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff

```

### Analisis

Masalah yang ditemukan:

1. Tidak ada atribut `Secure`
2. Tidak ada `HttpOnly` pada `laravel_session`
3. Tidak ada `SameSite`
4. Masa berlaku 30 hari (2592000 detik) terlalu lama

Risiko:

- Cookie dapat dikirim melalui HTTP
- Session dapat diakses melalui JavaScript (rentan XSS)
- Potensi CSRF lebih tinggi
- Session lifetime terlalu panjang

Status: **Tidak memenuhi WSTG-SESS-02**

---

## Sesudah Hardening

Hasil setelah konfigurasi diperbaiki:

```

┌──(sohyun㉿S14)-[~]
└─$ curl -I [https://192.168.20.145](https://192.168.20.145) -k

```

Response:

```

HTTP/1.1 200 OK
Set-Cookie: XSRF-TOKEN=...; Max-Age=7200; path=/; secure; samesite=lax
Set-Cookie: laravel_session=...; Max-Age=7200; path=/; secure; httponly; samesite=lax
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff

```

### Perubahan yang Dilakukan

1. `Secure` aktif
2. `HttpOnly` aktif
3. `SameSite=Lax`
4. Lifetime diturunkan menjadi 7200 detik (2 jam)

Status: **Compliant terhadap WSTG-SESS-02**

# WSTG-SESS-06 — Testing for Session Fixation

Pengujian ini bertujuan memastikan bahwa:

> Session ID berubah setelah proses autentikasi berhasil.

Jika session ID sebelum login sama dengan setelah login, maka aplikasi rentan terhadap session fixation.

---

## Pengujian Default Laravel

### Skenario 1

Sebelum login:

```

laravel-session=eyJpdiI6InIyTU5hMXYw...

```

Setelah login:

```

laravel-session=eyJpdiI6ImpUc1Zvajg5...

```

Session berubah ✅

---

### Skenario 2

Sebelum login:

```

laravel-session=eyJpdiI6IjRlUy9COUhN...

```

Setelah login:

```

laravel-session=eyJpdiI6InJYbWUvWFUx...

```

Session berubah kembali 

---

## Analisis

Laravel menggunakan `SessionGuard` pada guard `web`.  
Ketika `Auth::attempt()` berhasil, Laravel secara internal memanggil:

```

$this->session->migrate(true);

```

`migrate(true)` akan:

- Generate session ID baru
- Menghapus session lama

Artinya Laravel modern secara default sudah memitigasi session fixation.

Status: **Compliant terhadap WSTG-SESS-06**

---

# Kesimpulan

1. Konfigurasi awal cookie belum memenuhi standar keamanan.
2. Setelah hardening:
   - Cookie memiliki atribut keamanan lengkap.
   - Lifetime lebih rasional.
3. Laravel secara default sudah melakukan session migration saat login.
4. Tidak ditemukan kerentanan session fixation.
